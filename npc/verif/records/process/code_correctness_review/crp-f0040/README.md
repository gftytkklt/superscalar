## 已修部分、未支持能力与规范边界

现klib cpp.c已按1603f88修正acquire返回int、guard首字节完成标志、DSO为对象；注释明确只提供非并发初始化。`__cxa_guard_acquire`只读首字节，未占有“正在初始化”状态，`release`才置1；`__cxa_atexit`保留assert失败。AM默认C++17/-fno-exceptions/-fno-rtti，未加-fno-threadsafe-statics；本轮不改变这些选项，不将禁用编译器保护当作修复。

[Itanium ABI当前One-time Construction API](https://itanium-cxx-abi.github.io/cxx-abi/abi.html#once-ctor)允许不提供多线程支持的实现只用完成首字节；若要线程安全，则同步保护须持续到release/abort，不能只保护一次读取或发布。当前页面为§3.3.3，原审阅引用§3.3.2保留历史。该规范区分最小运行时与线程安全实现，不能据此把本项目尚未批准的受限能力直接当作完整ABI合规。

[公开C++草案stmt.dcl](https://eel.is/c++draft/stmt.dcl)区分并发进入等待与递归重入的未定义行为；本轮用两个独立上下文进入同一声明，不用同一调用链递归制造问题。访问的是当前公开草案，不冒充C++17出版文本；实际编译仍原std=c++17。

若要求同步，不能直接在单核协作线程上自旋：第二上下文可能等候已暂停在构造函数中的第一上下文，后者没有调度机会。需要结合可用调度/等待或初始化期间禁止切换的完整契约；后者还须处理构造函数主动yield/阻塞与长临界区。多核时还涉及可见性/原子指令及存储排序；异常abort/析构注册与退出顺序也不是完成首字节自动提供。本轮不新增这些协议。
